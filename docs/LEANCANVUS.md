# 린 캔버스 (Lean Canvas) - Untangle(가칭) 웹 프로토타입

> 작성 순서는 Running Lean의 순서(1~9번)를 따른다.

## 1. 문제 (Problem)

- **입력 단계 마찰**: 기존 할 일 앱은 우선순위·날짜·태그를 먼저 요구해, 생각이 떠오른 순간 기록하기 전에 막힌다.
- **분류 부담**: 쏟아낸 생각을 한 번에 분류하려다 압도되어 정리를 미루고, 미분류 항목이 쌓인다.
- **걱정이 행동으로 이어지지 않음**: 걱정은 머릿속에 쌓여 있을 뿐, 할 수 있는 행동으로 바뀌지 않는다.
- **기존 대안**: 종이 노트(형광펜으로 시간 구분), 일반 할 일 앱, 메모 앱. 모두 입력 마찰이 있거나 분류·실행 흐름이 끊긴다.

## 2. 고객 세그먼트 (Customer Segments)

- **핵심 사용자**: 생각이 많아 할 일 앱의 입력과 분류 단계에서 막히는 ADHD 성향의 개인 사용자
- **초기 고객(Early Adopter)**: 본인 1인. 웹 프로토타입으로 1~2주 직접 사용하며 검증한다.
- **확장 대상(MVP 이후)**: 같은 불편을 겪는 개인 사용자 (iPhone 앱 출시 시)

## 3. 가치 제안 (Unique Value Proposition)

> **"분류 부담 없이 한 줄씩 쏟아붓고, 나중에 걱정 / 해야 할 일로 간단히 정리한다."**

- 입력할 때는 아무것도 묻지 않는다 (입력 마찰 0).
- 정리는 나중에, 항목 하나씩만 한다.
- 걱정을 행동 한 줄로 바꿔 해야 할 일로 옮길 수 있다.
- 지우지 않고 보관하므로(Archive, 삭제 되돌리기) 마음 편히 분류할 수 있다.

**상위 개념(High-Level Concept)**: "ADHD 성향 사용자를 위한 브레인 덤프 + 간단 분류 앱"

## 4. 해결책 (Solution)

| 기능 ID | 해결책 | 해결하는 문제 |
|---------|--------|---------------|
| F001 | **빠른 입력**: 한 줄 입력 후 바로 추가, 입력창 유지, 여러 줄 붙여넣기 시 줄마다 항목 생성 | 입력 단계 마찰 |
| F002 | **항목 분류**: 걱정 / 해야 할 일 / Archive / 삭제 중 하나로 보내기, 삭제 직후 되돌리기 | 분류 부담 |
| F003 | **해야 할 일 설정**: 걸리는 시간(Quick 초록 / Focus 노랑)과 언제(오늘 / 이번 주 / 언젠가) | 실행할 일 고르기 어려움 |
| F004 | **걱정 보관과 행동 전환**: 걱정 보관, "행동으로 바꾸기", "행동으로 옮김" 표시 | 걱정이 행동으로 이어지지 않음 |
| F005 | **해야 할 일 보기와 완료**: 시점별 묶음 보기, 완료 시 Archive 이동 | 분류한 일을 꺼내 쓰기 |
| F006 | **Archive 보관**: 되돌리기, 완전 삭제 | 지우는 것에 대한 불안 |
| F007 | **대시보드 요약**: 오늘 할 일과 미분류 개수를 한 화면에 표시 | 앱을 열지 않고 현황 확인 |
| F010 | **기기 내 데이터 저장**: 브라우저 localStorage에 저장 | 로그인·서버 없이 사용 |

## 5. 경쟁우위 (Unfair Advantage)

모방하기 어려운 진짜 경쟁우위는 아직 없다. 프로토타입 단계에서 가질 수 있는 차별점은 다음과 같다.

- **본인이 곧 타깃 사용자**: 문제를 직접 겪고 있어 빠르게 검증하고 개선할 수 있다.
- **노트의 형광펜 구분을 디지털화한 UX**: Quick(초록) / Focus(노랑) 색 구분.
- **과감한 기능 제외**: AI, 우선순위, 태그, 캘린더, 알림 등을 넣지 않는 단순함.
- **걱정→행동 전환 흐름**: 걱정을 별도 상태로 두고 행동으로 연결하는 구조.
- **(검증 후 기대)** 사용 데이터와 iOS 위젯 연계 경험이 쌓이면 차별점이 될 수 있다.

## 6. 수익 흐름 (Revenue Stream)

- **MVP 단계: 없음** (1~2주 본인 사용 검증용 프로토타입)
- **향후 검토안**
  - iPhone 앱 유료 다운로드 또는 무료 + 프리미엄 구독
  - 프리미엄 후보: 기기 간 동기화, 위젯, 알림 등 MVP 이후 기능
- 수익 모델은 사용 검증 결과로 가치가 확인된 뒤 결정한다.

## 7. 비용 구조 (Cost Structure)

- **개발 시간**: 1인 개발 (웹 프로토타입 → iPhone 앱 전환)
- **인프라 비용**: 거의 없음. 서버·DB·로그인 없이 브라우저 localStorage만 사용한다.
- **도구 비용**: Next.js, React, Tailwind CSS, shadcn/ui 등 오픈소스 중심. 필요 시 호스팅(예: 정적 배포)
- **향후 발생 가능**: Apple Developer Program 연회비(iPhone 앱 배포 시), 동기화용 서버·DB 비용

## 8. 주요 지표 (Key Metrics)

1~2주 사용 검증 기간에 확인할 지표다. 모두 본인 사용 기록과 회고로 측정한다.

| 지표 | 확인할 내용 |
|------|-------------|
| 하루 평균 입력 개수 | 입력 마찰이 낮아 실제로 많이 쏟아내는가 (F001) |
| 사용 일수 | 1~2주 동안 꾸준히 열어 보는가 |
| 미분류 항목 개수 추이 | 분류를 미루지 않고 정리되는가 (F002, F007) |
| 걱정 → 행동 전환 비율 | 걱정이 행동으로 바뀌는가 (F004) |
| 해야 할 일 완료율 | 분류한 일을 실제로 처리하는가 (F005) |
| 대시보드 확인 빈도 | 위젯식 요약이 쓸모 있는가 (F007) |

## 9. 채널 (Channels)

- **MVP 단계**: 웹 프로토타입(본인 기기 브라우저 직접 사용). 별도 마케팅 채널 없음.
- **향후 검토안**
  - iPhone 앱: App Store
  - 같은 불편을 겪는 사용자 커뮤니티(ADHD 관련 커뮤니티, SNS 등)
  - 지인 추천, 사용 후기 공유

## 가정과 검증 계획

| 핵심 가정 | 검증 방법 | 성공 기준(예시) |
|-----------|-----------|-----------------|
| 입력 마찰이 없으면 더 많이, 자주 기록한다 | 1~2주 직접 사용, 일별 입력 개수 확인 | 매일 사용 |
| 분류를 나중에 한 번에 하나씩 하면 정리가 쌓이지 않는다 | 미분류 개수 추이 확인 | 미분류가 계속 늘지 않음 |
| 걱정을 행동으로 바꾸면 도움이 된다 | 전환 건수와 체감 기록 | 전환 후 완료 사례 확인 |
| 대시보드 요약만으로 오늘 할 일을 파악할 수 있다 | 대시보드 확인 빈도 기록 | iPhone 위젯 개발 진행 판단 |

> 성공 기준은 예시이며, 검증을 시작하기 전에 직접 조정한다.
