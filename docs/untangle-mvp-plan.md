# Untangle(가칭) 웹 프로토타입 MVP 기획서

> 상태: 초안 · 범위: 웹 프로토타입(1~2주 사용 검증용) · 최종 목표: iPhone 앱(SwiftUI)

## 1. 한 줄 정의와 문제

**머릿속을 분류 부담 없이 쏟아붓고, 나중에 간단히 정리하는 앱.**

ADHD가 있는 사람은 생각이 많은 게 문제가 아니라, 생각을 **꺼내는 순간의 마찰**과 **꺼내자마자 정리해야 한다는 압박**에서 막힌다. 대부분의 할 일 앱은 이 지점에서 실패한다.

- 입력할 때 제목, 날짜, 우선순위, 태그를 묻는다. 그 사이에 생각이 사라진다.
- 기능이 많아 앱을 "관리"하는 일이 또 하나의 할 일이 된다.
- 밀린 항목이 빨갛게 쌓여 죄책감만 남기고 앱을 열지 않게 된다.

Untangle은 이를 거꾸로 한다. **입력은 한 줄이면 끝**, 분류는 **나중에, 한 번에 하나씩**, 분류 선택지는 **아주 적게**.

## 2. 웹 프로토타입의 목적과 검증 가설

웹 버전은 출시용이 아니다. 실제로 1~2주 써 보며 **iOS 앱으로 만들 가치가 있는 UX인지** 확인하는 도구다. iOS 기술(위젯 등)을 그대로 재현하는 것이 목적이 아니다.

| # | 검증 가설 | 확인 방법 |
|---|---|---|
| H1 | 생각이 떠오른 뒤 **3초 안에** 입력을 시작할 수 있다 | 하루 메모의 "입력이 막힌 순간" 기록 |
| H2 | 분류를 **나중에** 하게 해 주면 입력이 부담스럽지 않고, 분류 시간도 감당할 만하다 | 정리 시간 체감, 미분류가 쌓이는 정도 |
| H3 | Quick/Focus 구분이 **실제로 "지금 뭐 하지?"를 줄여 준다** | 해야 할 일 중 고른 항목의 시간 구분 |
| H4 | 걱정을 **행동으로 바꾸기**가 걱정을 줄이는 데 도움이 된다 | 변환 횟수와 체감 변화 |
| H5 | 대시보드 한 화면이 위젯의 **"열지 않고 보는" 가치**를 대신할 수 있다 | 대시보드를 먼저 보게 되는지 |

## 3. UX 원칙 (ADHD 맞춤)

1. **입력 마찰 0**: 입력할 때는 아무것도 묻지 않는다. 우선순위, 날짜, 태그 없음.
2. **한 번에 한 가지 결정**: 정리 화면에서는 항목 하나에 선택지를 몇 개만 보여 준다.
3. **죄책감 유발 금지**: 연속 기록, 완료율, 빨간 지연 표시, 못 한 일 강조를 쓰지 않는다. 밀린 일은 조용히 그대로 둔다.
4. **되돌릴 수 있는 안전망**: 잘못 눌러도 잃어버리지 않는다. 지우기 대신 Archive가 기본 출구다.
5. **압박 없는 빈 화면**: 비어 있으면 "아직 비어 있어요" 정도의 부드러운 문구. 할 일을 재촉하지 않는다.
6. **선택지는 적게**: 모든 분류는 2~4개 선택지 안에서 끝난다.

## 4. 핵심 흐름

```text
         ┌─────────────┐
         │ Brain Dump  │  한 줄씩 쏟아붓기 (미분류)
         └──────┬──────┘
                │ 나중에 직접 하나씩 분류
   ┌────────┬───┴────┬───────────┐
   ▼        ▼        ▼           ▼
 걱정    해야 할 일   삭제      Archive
   │        │                     ▲
   │        │  완료 ──────────────┘
   │        │
   └── "행동으로 바꾸기" ──► 해야 할 일 (새 항목)
```

- Brain Dump 항목은 **자동으로 분류되지 않는다**. 사용자가 직접 4곳 중 하나로 보낸다.
- 걱정은 그대로 둘 수도 있고, 행동으로 바꿀 수도 있다.
  - 예: "취업이 걱정된다" → 행동으로 바꾸기 → "이력서 수정하기"
- 해야 할 일로 보낼 때만 두 가지를 묻는다: **얼마나 걸릴까요? / 언제 할까요?**

## 5. 화면별 명세

### 5-1. Brain Dump (홈)

- **목적**: 생각을 가장 빠르게 꺼낸다. 앱을 열면 바로 입력할 수 있다.
- **보이는 것**: 항상 맨 위에 있는 입력창, 그 아래 아직 분류하지 않은 항목 목록(최신 순).
- **행동**
  - 한 줄 입력 후 확인 → 목록에 추가되고 입력창은 비워진 채 유지된다. 연속 입력이 가능하다.
  - 항목마다 걱정 / 해야 할 일 / 삭제 / Archive 중 하나로 이동.
- **묻지 않는 것**: 제목, 날짜, 우선순위, 태그.
- **빈 상태**: "머릿속에 있는 걸 그냥 적어 보세요. 정리는 나중에 해도 돼요."

### 5-2. 걱정

- **목적**: 걱정을 쌓아 두지 않고 눈에 보이는 곳에 내려놓는다.
- **보이는 것**: 걱정으로 옮긴 항목 목록.
- **행동**
  - 그대로 두기.
  - **행동으로 바꾸기**: 걱정 문장을 보면서 행동 한 줄을 입력하면 "해야 할 일" 항목이 만들어진다. 이때 걸리는 시간과 시점을 함께 고른다.
  - Archive 또는 삭제.
- **빈 상태**: "지금 적어 둔 걱정이 없어요."

### 5-3. 해야 할 일

Brain Dump에서 해야 할 일로 보낼 때 두 가지를 고른다.

**① 얼마나 걸릴까요?**

| 선택 | 의미 | 색 |
|---|---|---|
| Quick | 10분 이하 | 초록 계열 |
| Focus | 30분 이상 | 노랑 계열 |

노트에 형광펜으로 구분하던 방식을 디지털로 옮긴 것이다. 색만 봐도 구분되도록 하고, 색에만 의존하지 않도록 글자(Quick/Focus)도 함께 쓴다.

**② 언제 할까요?**

| 선택 | 의미 |
|---|---|
| 오늘 | 오늘 안에 하고 싶다 |
| 이번 주 | 이번 주 안에 하고 싶다 |
| 언젠가 | 날짜는 정하지 않았다 |

정확한 날짜와 시간은 받지 않는다.

- **보이는 것**: 시점별(오늘 / 이번 주 / 언젠가)로 묶은 목록. 각 항목에 Quick/Focus 색 표시.
- **행동**: 완료(→ Archive), 시간·시점 바꾸기, 삭제.
- **빈 상태**: "오늘 할 일이 비어 있어요."

### 5-4. Archive

- **목적**: 끝낸 일과 지금은 필요 없는 생각을 **지우지 않고** 치워 둔다.
- **보이는 것**: Archive로 보낸 항목 목록(최근 순).
- **행동**: 원래 자리(Brain Dump)로 되돌리기, 완전히 삭제.

### 5-5. 대시보드 (iOS 위젯의 웹 대체)

- **목적**: 앱 안을 돌아다니지 않고 **지금 필요한 것만** 한 화면에서 본다.
- **보이는 것**
  - 오늘 해야 할 일(Quick/Focus 색 표시).
  - 미분류 Brain Dump가 몇 개 쌓였는지(숫자 하나, 재촉하는 문구 없음).
  - 빠른 입력창.
- **보이지 않는 것**: 완료율, 연속 기록, 지연 표시 같은 압박 요소.

## 6. iOS 기능 → 웹 대체 매핑

| iOS 최종 앱 | 웹 프로토타입의 대체 | 웹에서 검증 못 하는 것 |
|---|---|---|
| 홈 화면 위젯 | 대시보드 | 홈 화면에서 앱을 열지 않고 본다는 경험 |
| 잠금화면 위젯 | 대시보드의 "오늘" 한 줄 요약 카드 | 잠금 상태에서의 즉시 접근 |
| 빠른 입력 | 모든 화면 상단에 항상 보이는 입력창 | 위젯/단축 동작으로 앱을 열기 전에 입력하는 속도 |
| 스와이프 인터랙션 | 항목 카드 위의 분류 버튼 | 한 손 스와이프의 손맛 |

웹에서는 "무엇을 보여 주고, 몇 번 눌러 분류가 끝나는가"를 검증하고, 손맛·접근 속도는 iOS 단계에서 다시 검증한다.

## 7. MVP에 넣지 않는 것

| 제외 항목 | 이유 |
|---|---|
| AI | 정리를 대신해 주는 순간 "내가 정리했다"는 감각이 사라지고, 검증할 대상이 흐려진다 |
| 우선순위 | 입력과 분류의 결정 부담을 키운다. Quick/Focus와 시점만으로 충분한지 먼저 본다 |
| 프로젝트 | 구조를 만드는 일이 또 하나의 할 일이 된다 |
| 태그 | 입력·분류 마찰을 늘린다 |
| 캘린더 | 정확한 일정 관리는 이 앱의 목적이 아니다 |
| 정확한 마감 시간 | 마감 압박은 죄책감의 원인이 된다 |
| 반복 일정 | 습관·루틴 관리는 다른 문제다 |
| 알림 | 재촉하지 않는 것이 원칙이다. 필요성은 사용해 본 뒤 판단한다 |
| 통계 | 숫자는 비교와 죄책감을 낳는다. 검증은 직접 쓰는 메모로 한다 |
| 로그인 | 검증 대상이 아니다. 혼자 쓰는 프로토타입이다 |
| 서버 | 데이터는 사용하는 기기 안에만 둔다. 동기화는 검증 대상이 아니다 |
| 소셜 기능 | 공유·비교는 이 앱의 안전한 분위기와 맞지 않는다 |

## 8. 열린 질문과 기획자의 기본 제안

아래는 원문에 정해져 있지 않아 기획서에서 **임시로 결정**한 것들이다. 사용해 보며 바꿀 수 있다.

| # | 질문 | 기본 제안 | 이유 |
|---|---|---|---|
| Q1 | Quick(10분 이하)과 Focus(30분 이상) **사이의 10~30분**은? | 선택지는 두 개만 둔다. 애매하면 사용자가 더 가까운 쪽을 고른다 | 선택지를 늘리면 결정 피로가 생긴다. 쓰다가 애매함이 크면 그때 세 번째 선택지를 검토한다 |
| Q2 | 해야 할 일의 **완료 처리**는? | 완료하면 Archive로 이동한다. 별도의 "완료됨" 목록은 없다 | 완료 목록이 생기면 달성 수를 세게 된다 |
| Q3 | 걱정을 행동으로 바꾼 뒤 **원래 걱정**은? | 걱정에 그대로 남기고 "행동으로 옮김" 표시만 한다. 원하면 Archive | 걱정이 사라지지 않는 경험도 그대로 보여 주기 위해서 |
| Q4 | **어제의 "오늘" 항목**은? | 자동으로 옮기거나 경고하지 않는다. 그대로 두고 대시보드에서 "어제 것"으로 조용히 구분만 한다 | 못 한 일을 빨갛게 보여 주지 않는 원칙 |
| Q5 | **삭제를 잘못 눌렀을 때**는? | 확인창 대신 짧게 "되돌리기"를 보여 준다 | 확인창은 흐름을 끊는다 |
| Q6 | 여러 줄을 한꺼번에 **붙여넣으면**? | 줄마다 항목 하나로 나눈다 | 노트에 적은 걸 옮길 때 편하다 |
| Q7 | 입력한 항목을 **수정**할 수 있나? | 가능하다. 단 분류 화면에서만 문구를 고칠 수 있다 | 입력 화면을 단순하게 지킨다 |

## 9. 1~2주 검증 계획

앱에는 통계가 없으므로, 검증은 **사용자가 직접 남기는 짧은 메모**로 한다.

**하루 메모 (3줄, 저녁에)**
1. 오늘 몇 번 열었고, 어떤 상황이었나?
2. 입력하다가 막히거나 귀찮았던 순간이 있었나?
3. 오늘 가장 도움이 된 것 / 가장 거슬린 것 한 가지.

**주차별 질문**
- 1주 차: 생각이 떠올랐을 때 앱을 먼저 떠올리는가? 분류를 몰아서 하는 시간이 부담스럽지 않았는가?
- 2주 차: Quick/Focus 구분을 실제로 보고 골랐는가? 걱정→행동 변환을 몇 번 썼는가? 대시보드를 먼저 보게 되었는가?

**종료 시 판단**

| 판단 | 기준 |
|---|---|
| iOS로 가져갈 것 | 2주 동안 자연스럽게 계속 쓴 흐름 |
| 바꿀 것 | 써 보니 막히거나 안 쓰게 된 부분 (예: 선택지 수, 화면 구성) |
| 버릴 것 | 한 번도 안 쓴 기능 |
| 중단 | 1주 안에 거의 안 열게 된다면 이유를 먼저 정리하고 방향을 다시 잡는다 |

## 10. 다음 단계 (이번 범위 밖)

이번 문서는 **무엇을 만들지**까지만 정한다. 이후 순서는 다음과 같이 제안한다.

1. 이 기획서의 8번(열린 질문)을 확정한다.
2. 웹 프로토타입 스타터 킷을 정한다(기술 선택, 폴더 구조, 화면 뼈대). 사용자가 코드를 이해하고 고칠 수 있는 단순한 구조를 우선한다.
3. Brain Dump 입력과 분류부터 구현해 하루 써 본다.
4. 해야 할 일, 걱정, Archive, 대시보드 순으로 넓힌다.
